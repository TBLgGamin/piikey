# piikey: agent instructions

Pure backend in Rust, Windows-only. CPU parallelism through rayon.
A lightweight PII masker: validated-regex detection, format-preserving
watermarked proxies, DPAPI-protected vault, reversible deanonymization.

## Learn the stack before writing code

- Rust: read [The Rust Book](https://doc.rust-lang.org/book/) (offline: `rustup doc --book`).
- rayon: [docs.rs/rayon](https://docs.rs/rayon). `par_iter`, `par_chunks`, `rayon::join`.
- regex-automata: [docs.rs/regex-automata](https://docs.rs/regex-automata) (`meta::Regex`, multi-pattern).
- WinRT (`windows` crate) APIs churn: read `cargo doc` for the pinned version, never write them from memory.
  The same goes for `zip`, `quick-xml`, `lopdf`, `mail-parser`, `cfb`, `chacha20poly1305`, `uiautomation`.
- App (`app/`): `hudsucker` (MITM proxy), `windows-reactor` (WinUI 3), `sysproxy`, `netstat2`, `sysinfo`,
  `uiautomation` (UI Automation, wrapped safely: raw `windows` UIA calls are `unsafe`), `clipboard-win`,
  `notify` (file-system change notifications for monitored locations: `ReadDirectoryChangesW` is `unsafe`, so the crate wraps it),
  `rfd` (the Windows folder and file pickers of the Browse buttons: `IFileOpenDialog` is COM and `unsafe`).
  `windows-reactor` is pinned to a git revision because the tray/`Application` API
  (`App::run_application`, `NotifyIcon`) is not in a crates.io release; the revision is on the fork
  `TBLgGamin/windows-rs` (microsoft/windows-rs at 20f6de7 plus three fixes: hiding a window's open
  dialogs in the adapter's drop, a list's selection set after the items its update adds, and an `ItemsRepeater` row stretched across its width).
  Read its source under `~/.cargo/git/checkouts/windows-rs-*/<rev>/crates/libs/reactor` and the
  samples in `crates/samples/reactor`; the docs.rs pages describe the older release.
- Cloud sources (`src/sources/`): each provider's official REST reference (Microsoft Graph, Google Drive API v3, Dropbox API v2, Box API 2.0) and its sign-in rules (OAuth 2.0 authorization code with PKCE over a loopback redirect, client credentials, Google's JWT bearer grant); never write an endpoint, scope or redirect rule from memory. HTTP is `ureq` 3 on Windows' own TLS (`native-tls`), RS256 signing is `ring`, the encodings `base64`.

## Rules

- **Parallelize whenever possible.**
  - Data-parallel CPU work: rayon (`par_iter`, `par_chunks`, `rayon::join` for divide-and-conquer).
    Keep splits balanced; never hand-roll threads or locks for data-parallel work.
- `unsafe` is forbidden (`Cargo.toml` `[lints.rust]`).
- Library code returns `Result`; no `unwrap`/`expect`/`todo!`/`dbg!` (clippy rejects them).
- Clippy runs `pedantic` with `-D warnings`. Fix the code, do not `#[allow]` it,
  unless the lint is wrong for that line; then allow on the narrowest item with a comment why.
- `EntityKind` discriminants and the vault file layout are on-disk formats: never renumber or reorder.
- Every proxy generator must produce values its own detector finds again (see `proxy` tests).
- Detectors implement `detect::Detector` (`detect_batch` for batch-aware ones such as `NerDetector`).
- CI has no detection model: every test must pass without it; model tests are `#[ignore]` (`tests/ner_model.rs`).
- Keep dependencies minimal; justify every new crate.
- The exe's own path (`current_exe()`) is for the process itself. A path that another program is to run (the Explorer verb, the sign-in `RunOnce` entry, the start-at-sign-in `Run` value) comes from `sys::launch_path()`: in the Microsoft Store (MSIX) build the folder of the exe changes with every version and Windows keeps it closed to other programs, so only the execution alias works.
- User-facing text (UI, tray, notices, Explorer verb, README, docs) says: personal data (not PII), type (not kind), stand-in (never proxy for a value), swap and turn back, vault, protected sites and apps (not programs), Protection, Masking, Highlighting, Inventory, Monitor (a location's switch; the word Watch does not appear on screen), Detection, certificate. The words Keyed, Home and PII do not appear on screen: a window test fails if drawn text contains "PII", "keyed", "program" or "kind". Code identifiers and the CLI's `kind` flags keep their names.
- API docs are generated: run `cargo api-docs`, which rewrites `docs/api/openapi.json` and `docs/api/README.md` from the code (never hand-edit them; the pre-commit hook regenerates and stages both). The hand-written prose in `docs/api/prose.toml` is flagged when its operation changes (`cargo api-docs --check-prose` prints the flags, and a test fails on them): read it, fix it if it is untrue, then `cargo api-docs --accept <op>`.
- A cloud item's path is virtual (`\\Google Drive\jan@acme.com\My Drive\a.docx`, see `sources::parse_virtual`). Never hand one to the file system (`fs::metadata`, `is_dir`, `files::walk`, `Inventory::scan_paths`/`refresh`, the notify watcher) or to Explorer: Windows takes its first part for a server name and waits for it. Split locations with `sources::split_roots`, scan the cloud ones with `sources::scan_clouds`, open a cloud item through its web page. Provider logos are never recoloured or redrawn (`app/assets/providers/README.md`), and Box has none.
- The window and its messages never show the virtual form of a cloud path: `sources::display_path` writes `jan@acme.com › My Drive › Clients › a.docx` (the account's name, the folders, the file; the provider is told by its logo) and `sources::shown` is the same for a message, leaving a local path as it is. The API, the CLI and the export report keep the address form. A provider's name drawn for an account goes through `assets::provider_name`, so a debug-only fake never reads as a real provider.

## Commits, versions and releases

- Every commit message is a [Conventional Commit](https://www.conventionalcommits.org):
  `feat|fix|perf|refactor|docs|build|ci|chore|style|test|revert`, optional `(scope)`, `!` for breaking.
  The `commit-msg` hook (commitlint) and CI reject anything else. PRs are squash-merged, so a PR title is a commit message too.
- `feat` bumps the minor version, `fix`/`perf` the patch (also before 1.0: `features_always_increment_minor`).
- Never edit `version` in any `Cargo.toml`, never edit `CHANGELOG.md`, never create or push tags.
  The version lives only in the root `Cargo.toml` `[workspace.package]`; both packages inherit it.
  release-plz keeps a `chore: release vX.Y.Z` PR open; merging it tags `vX.Y.Z`, publishes the GitHub Release
  and builds the portable zip and installer. `scripts/release-guard.mjs` (pre-commit, pre-push, CI) refuses the rest.

## Before committing

```sh
cargo fmt              # format
cargo lint             # clippy, all targets, -D warnings (alias in .cargo/config.toml)
cargo test --all-targets
```

Husky runs `cargo fmt-check` + `cargo lint` on commit (and `cargo api-docs`, which it stages) and `cargo test --all-targets` on push.
CI runs all three on Windows. Never bypass hooks with `--no-verify`.

## Layout

|Path|Purpose|
|---|---|
|`src/detect/`|`EntityKind`, `Detector` trait, `RegexDetector`, validators|
|`src/detect/issued.rs`|`IssuedProxies`: finds the proxies the vault issued, of every kind, by exact whole-word lookup (a few automata "levels", so a growing vault is not rebuilt each time); the engine restores with it, and masks text that reads like an earlier proxy of a listed kind. `Words`: whether a candidate proxy would read like text that stays|
|`src/detect/composite.rs`|`CompositeDetector`: runs several detectors over a batch, the earlier span wins on overlap; each later detector is told what the earlier ones kept (`taken`)|
|`src/detect/ner/`|`NerDetector`: the on-device PII model (ONNX Runtime via `ort`, `tokenizers`); CPU session always, plus a DirectML GPU session in hybrid mode that takes large batches from the other end of the queue; `session.rs` (the sessions, the model with its tokenizer, the CPU/hybrid choice in `device.cfg`), `chunks.rs` (texts cut into chunks, data blobs left out), `windows.rs` (token windows, padded batches, reading the logits), `queue.rs` (the queue CPU and GPU pull from at opposite ends), `files.rs` (pinned model files, folder), `fetch.rs` (first-run download with `curl.exe` (resumes) and SHA-256 check with `certutil`; only a real hash mismatch deletes a file), `labels.rs` (model labels -> `EntityKind`, one `TYPES` table), `decode.rs` (token logits -> word spans), `gate.rs` (skips texts with nothing to find; per-text result cache that keeps the first answer)|
|`eval/`, `examples/pii_eval/`|quality benchmark: `fetch.py` (sampled public corpora), `handmade.py` (hand-labelled NL/EN/DE set), `labels.toml` (label mapping), `cargo run --release --example pii_eval`|
|`src/restore/`|streaming tolerant `Restorer`: exact, typo and component tiers over a session `Scope`, plus a `ProxyFinder` (the vault's own lookup, `Engine`) merged into the same single pass (the `_with` methods), so restored text is never read again and a value equal to another proxy comes back once|
|`src/proxy/`|format-preserving proxy generators, watermark|
|`src/vault/`|DPAPI-wrapped, encrypted append-only vault; `resolve(new, avoid)` never issues a proxy `avoid` turns down; `search`, `export` (JSON/CSV), and `forget`/`wipe`, the only rewrite path: it re-seals the kept records under a new vault id and swaps the file in through `<vault>.compact`, which `open` and every later write finish after a crash and other processes notice by the changed id|
|`src/engine.rs`|anonymize/deanonymize over batches; `scan` detects without touching the vault (and ignores proxies the vault issued); `forget`/`wipe`; `Engine::plan` documents what a round trip promises (new proxies avoid the text that stays, text equal to an earlier listed proxy is masked, every proxy is found by exact lookup)|
|`src/formats/`|format sniffing, text/OOXML/ODF/PDF/image/eml/msg; one `Pass` carries a rewrite (`process`), a restore through a `Restorer` (`restore`: the tolerant tiers and every proxy of the vault in one pass over each text, so documents and mail get typo and lone-name tolerance too) or a scan (`scan`, and `findings`: every value whole with its type, the text around it and a `Location`) through every format. `findings(engine, bytes, report)` reports as it goes (`Report::Found` in batches of 1,000, `Report::Busy` for the line of progress; the callback says whether to go on, may be called from several threads, and a stop ends the read after the group of texts the model is in): the values the patterns find first, in reading order, then what the model finds a group of texts (one 64 KiB chunk) at a time (`Engine::scan_steps` over `Detector::detect_batch_steps`), so a huge text shows its emails and numbers in a moment while the model is still at the names; the steps of one call hold what `scan` counts, and a message (`Layout::Raw`) is placed once its call is done. `places.rs` and `sheets.rs` say where a value stands, and only for a read of findings, at the file's own level: a line and column in a text (lines end at `\n`, `\r\n` or `\r`, columns count characters, found by a cursor that walks forward so one huge line stays linear), the page of a PDF (the text layers are read first, then the pages that are pictures through OCR with `Busy::Pages` progress), the sheet and cell of an xlsx or ods, the line of the raw file for an `.eml`, the slide and shape of a presentation and its notes (`slides.rs`: the slide is where `ppt/presentation.xml` lists it, not the number in its part's name; |`src/ocr.rs`|Windows.Media.Ocr + Windows.Data.Pdf rendering|
|`src/sys.rs`|Windows plumbing shared by the CLI and the app: `data_dir()`, `write_atomic` (a temporary file of its own per call, so two processes never share one), `write_new` (never replaces a file), `try_lock`/`lock_within`/`FileLock`, `fill_random`, `dpapi_protect`/`dpapi_unprotect` (the vault key and the app's CA key), `is_under`/`same_path`/`path_key` (Windows path comparison), `volume_len` (how many leading components of a path are its drive or share with the root: the top of the dashboard's tree), `system_dir`/`system_command`/`run_system_tool` (System32 tools, no console window), `is_packaged` (the process runs from the Microsoft Store MSIX package) and `launch_path` (what the Explorer verb and the sign-in `RunOnce` entry run to start the exe: the exe itself, or in the package its execution alias under `ALIAS_DIR`, because the package folder changes with every version and is closed to other programs)|
